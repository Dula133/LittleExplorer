# LittleExplorer Simple+ V0.1 原版保护基线

任务：LE-SIMPLE-PLUS-PHASE0-001。本检查点只增加文档、测试与截图，不增加汽车功能。

## 产品定位与观察事实

孩子已经实际比较过原版与豪华驾驶舱版本，明确更喜欢原版的简洁、易辨认与直接操作。
这是本项目采用 Simple+ 路线的产品依据，不将这项观察扩展为能力、人格或心理判断。

Simple+ 保留“拖动观察、点零件立即得到针对性解释”的探索方式。在原版局部增加灯光细分和雨量，
不要求儿童学习豪华驾驶舱、驾驶模拟流程或大型控制面板。

8. 点击雨刮器：下雨，约三秒后刮雨；再点停止下雨，雨刮继续约 1.5 秒后缓动停放，
   或按原计时自动结束。

## 自动 QA 的运行方法

需要 Node.js、Python 3、FFmpeg、系统 Chromium 和 `playwright-core@1.58.2`。
QA 依赖安装在仓库外，避免改变产品依赖与锁文件。例如：

```sh
npm install --prefix /tmp/le-simple-plus-qa playwright-core@1.58.2
PLAYWRIGHT_MODULE=/tmp/le-simple-plus-qa/node_modules/playwright-core \
CHROMIUM_BIN=/usr/bin/chromium \
node tools/qa_car_simple_plus.cjs
```

脚本自行启动仅监听 `127.0.0.1`、使用随机端口的 Python HTTP 静态服务器，并在结束时关闭自己的
浏览器和服务器。默认输出到新的系统临时目录，最后打印路径。可用 `LE_QA_OUT` 指定独立证据目录。
默认运行不会改写已提交的基线。

基线创建后，沿用相同的 `PLAYWRIGHT_MODULE` / `CHROMIUM_BIN` 配置，
用 `node tools/qa_car_simple_plus.cjs --visual-only` 独立重复八张截图，
核对相机、布局、状态和零件结构。此模式报告 `VISUAL_PASS`，不重跑配音和十九场景测试，
不能代替完整 QA 的 `PASS`。完整录制不能与此选项同时使用。

创建原始基线时使用 `--record-baseline`。它要求 HEAD 恰好等于原版 SHA，所有原版文件一致，
且持久化基线目录尚不存在；任何测试失败都不会将临时截图固化为正式基线。
成功后才复制到 `docs/baselines/simple-plus/`。检查点提交之后请使用普通验证模式，不能重新记录。

固定环境包含：Chromium 版本、UTC、`zh-CN`、DPR 1、随机种子 20261016、固定日期和逻辑时钟、
同一软件渲染后端、视口、相机与日夜状态。动画按固定 50ms 步长推进原有 rAF/update，
遵守原来的 dt 上限。实际版本与参数以 `manifest.json` 为准。
浏览器版本或字体环境改变时，应复现旧环境，不能通过静默刷新基线消除差异。

首页相机保留原 `js/home.js` 的包围球适配：FOV 32°，
`d = radius / sin(16°) × 1.12`，位置为
`[sin(0.9) × d × 0.85, centerY + d × 0.42, cos(0.9) × d × 0.85]`，
看向 `[0, centerY × 0.95, 0]`；卡片以每秒 0.35 弧度旋转，采用原每帧四张的轮转绘制。
首页截图固定在逻辑时间 400ms；汽车截图的实际相机向量和动画状态逐张保存在 manifest 中。

## 测试真实性与覆盖

- 零件通过实际 Three.js 射线找到可见且未被 UI 遮挡的坐标，再由浏览器发送触控输入。
  记录 `isTrusted`、坐标、目标及实际选中结果；不用 `dispatchEvent()`、DOM `.click()`、
  直接调用零件 `action()` 或篡改汽车状态作为交互通过依据。
- 每个汽车用例使用独立上下文和时钟起点，不跨页面回放累积的时钟控制历史。
  固定时钟只控制动画、原计时器和截图条件，不代替输入或实现产品逻辑。
  雨刮自动到期用时间跳进验证期限，再正常推进动画检查衰减；不是实时等待十五秒的录像。
- 检查默认相机、原三大按钮、唯一零件归属、布局、原灯光昼夜、单扇车门、雨刮三秒延迟、
  启动/停止与车轮动画、讲解文字、透视、拆开及准确归位。
- 在 390×844 和 360×800 下重复汽车交互；桌面截图采用 1280×900。
- 首页验证二十张卡、汽车画布实际有像素和汽车链接可用；其余十九个场景逐一加载并检查 WebGL。
- 运行原 `tools/check_voice.py`，校验映射及两套文件；FFmpeg 解码所有现有 MP3。
  两套原车灯讲解另用非静音、真实时钟、原生播放验证，等待真实 `playing` 和 `ended` 事件。
  对离线 Audio 对象只添加被动观察监听，不替换音频、播放结果或完成回调。
- 收集 JS 异常、console error、HTTP 失败、请求失败及 WebGL 上下文丢失。
  HTTP 服务器也检查资源失败。原版没有 `favicon.ico`，自动请求它产生的 404 单列为已知原版情况；
  对应 console 消息必须精确指向本服务器的 `/favicon.ico` 且为资源 404 才属于这条例外。
  不改页面或补造图标，不忽略其他资源或脚本错误。

## 截图与比较规则

持久化截图包含：首页 390×844、汽车默认 390×844、默认 360×800、默认 1280×900、
390×844 夜景、开门、透视和拆开，共八张 PNG。PNG 使用无损压缩，不增加截图工具依赖。

普通验证同时检查截图文件校验和，以及重新拍摄时的相机、逻辑时间、状态、页面布局、
关键节点、零件名称/讲解、网格结构与归属。SHA256 用于标识文件，不能把所有像素差异直接判成产品错误。
数据比较先统一为与保存文件相同的 JSON 表示（例如 `-0` 保存为 `0`），随后逐项精确比较，
不以放宽相机、布局或节点误差来消除差异。
本检查点保存完整 QA 的 `qa-report.json` 和独立复拍的 `verification-report.json`，
区分完整验收与视觉复现；以后运行的临时输出不会覆盖这些已保存证据。

人工验收时并排查看基线和候选截图：首先排除浏览器、字体、DPR、相机、动画相位和渲染后端差异，
再判断差异是否落在批准的局部灯具、雨滴和轻量入口范围内。
不可用豪华分支替换原版参考，也不可为了让候选通过而重新记录原版。

## 验证边界

本检查点使用桌面 Chromium 和软件 WebGL 渲染。移动视口是浏览器模拟，不等于 HarmonyOS 实机。
自动化射线定位能命中零件，不代表已验证儿童能自然发现它，或真实手指具有相同命中率。
尚未验证华为手机 GPU 性能、浏览器音频策略、扬声器听感、系统中文语音及前后台切换。
原生 MP3 播放和解码通过也不代表已经有人通过耳朵听过内容与音量。
其他十九场景为加载冒烟，不声称完成各场景全部功能验收。

后续实机需记录机型、HarmonyOS/浏览器版本、访问 commit，实际操作旋转、点灯、点门、雨刮、
三大按钮、静音与声音切换，记录操作事实与儿童原话；不得据此生成能力或人格判断。
